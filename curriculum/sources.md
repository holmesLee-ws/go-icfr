# 근거 대장

커리큘럼과 튜터가 인용하는 법령·기준의 대장이다. 튜터는 여기 있는 것이거나, 세션 중 공식 출처로 확인한 것만 근거로 말한다(규칙은 [tutor/sources.md](../tutor/sources.md)).

- 조회일은 모두 공식 페이지·첨부 원문을 직접 읽은 날이다. 요지는 직접 요약했다. 조문 원문은 두지 않는다.
- `변동`이 「예」인 행은 조회일 기준 3년 안에 개정·시행됐거나, 단계 적용·유예·개정 예고 중인 것이다. 튜터는 학습자의 판단에 쓰기 직전에 그 세션에서 한 번 다시 확인한다.
- 용어 주의: 국내 평가·보고 가이드라인은 「유의한 미비점」, 회계감사기준(감사기준서 1100·265)은 「유의적 미비점」이라고 쓴다. 같은 개념(영문 significant deficiency)이다. material weakness는 국내 용어 「중요한 취약점」으로 통일한다. COSO의 「major deficiency」(G02)는 프레임워크 차원의 개념이라 material weakness와 같은 말이 아니다.
- 공식 출처끼리 표현이 다르면(예: K06과 K07의 2030년 대상 표기) 튜터는 차이를 그대로 말하고 단정하지 않는다.
- URL 칸에 출처가 둘 이상이면 공백으로 나눠 적는다.
- 리포 관리자: 행을 고치면 조회일을 바꾸고 `node tools/check.mjs`를 돌린다.

## 접근 메모 (최신 확인 때 먼저 쓰는 경로)

- 국가법령정보센터(law.go.kr): 조문 원문의 1차 출처다. 법령명 경로(`https://www.law.go.kr/법령/주식회사등의외부감사에관한법률`)로 연다. 본문이 안 읽히거나 점검 중이면 금융감독원 「내부회계관리제도 관련 FAQ」(K14)가 조문 번호를 명시해 인용하므로 그것으로 대신 확인하고, 그렇게 했다고 말한다. 다만 FAQ 본문은 첨부(HWPX)라 세션 중 WebFetch로는 읽히지 않는다(G2 실측). 그래서 세션 중 확인 순서는 국가법령정보센터 → 국회 법률정보시스템(likms.assembly.go.kr) → 금융위원회 보도자료 HTML(본문이 바로 읽힌다, 예: K05·K06 URL) → 실패 문구다.
- 금융위원회 보도자료(fsc.go.kr `/no010101/번호`): HTML 본문이 바로 읽힌다. 목록 검색은 `https://www.fsc.go.kr/no010101?srchKey=all&srchText=내부회계`.
- 금융감독원(fss.or.kr): 보도자료·자료실 페이지는 요약만 HTML이고 본문은 첨부(PDF·HWP)다. 자료실 목록 `https://www.fss.or.kr/fss/bbs/B0000155/list.do?menuNo=201177`.
- 한국공인회계사회(kicpa.or.kr): `/board/read.brd?boardId=…&bltnNo=…` 형식은 HTML이 바로 읽힌다.
- 내부회계관리제도운영위원회(k-icfr.org): 금융감독원 보도자료가 운영위원회 공식 홈페이지로 안내하는 곳이다.
- 국회 의안정보시스템(likms.assembly.go.kr): 계류 법안(K08)의 현재 상태를 확인하는 곳이다. 의안번호로 검색한다.
- G2 실측(2026-11-14, `claude -p` 프로젝트 설정·신뢰 수락 뒤 WebFetch, `변동` 항목 기준): 금융위원회 보도자료 HTML(K05·K06)과 영국 FRC 코드 페이지(G15)는 본문이 읽혔다(조문 번호는 보도자료 본문에 없다). 금융감독원 자료실·보도자료(K07·K14)는 요약만 읽혔다(본문은 첨부). 국가법령정보센터는 그날 점검 안내만 돌려줬다.
- PCAOB(pcaobus.org): 개별 기준 HTML은 자동 조회가 거부될 수 있다. 기준서 묶음 PDF(G10 URL)를 쓴다. SEC 규칙 조문은 eCFR(ecfr.gov) 페이지가 읽힌다.
